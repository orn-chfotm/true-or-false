# Opinion Brief 도메인 정의

## 1. 서비스 정의

Opinion Brief는 특정 주제에 대해 적합한 사용자를 선별하고, 사용자의 근거 있는 투표를 AI로 검수한 뒤, 대중 또는 특정 타깃 집단의 시선과 판단을 보여주는 보상형 의견 판별 플랫폼이다.

이 서비스는 단순 투표 사이트가 아니다. 사용자가 투표를 제출했다고 해서 바로 결과에 반영되지 않는다. 모든 투표는 근거 의견을 포함해야 하며, AI 검수를 통과한 의견만 유효 투표로 반영된다.

핵심 문장:

```text
주제별로 적합한 사람을 선별해, 근거 있는 투표와 경험 데이터를 수집하고,
AI 검증을 거쳐 대중/타깃 집단의 판단을 보여주는 보상형 의견 판별 플랫폼
```

## 2. 핵심 가치

Opinion Brief가 제공하는 가치는 아래와 같다.

- 특정 주제에 대한 대중의 시선 수집
- 특정 유형 사용자 또는 경험자의 의견 수집
- 주장, 찬반, 선택 비교에 대한 판단 수집
- AI를 통한 근거 타당성 검수
- 무의미하거나 부적절한 투표의 무효 처리
- 유효한 기여에 대한 포인트 보상
- 결과가 언제, 어떤 조건에서, 몇 명의 유효 투표로 만들어졌는지 명확히 표시

## 3. 주제 유형

서비스는 특정 주제 도메인에 한정되지 않는다. 대신 모든 주제를 아래 유형 중 하나로 분류해 처리한다.

### 3.1 주장 검증형

어떤 주장이 진실에 가까운지, 거짓에 가까운지, 또는 불확실한지 판단하는 유형이다.

예시:

```text
전자레인지에 플라스틱 용기를 돌리면 위험하다.
AI는 특정 직군의 일자리를 줄인다.
```

결과 형태:

- 진실에 가까움
- 거짓에 가까움
- 불확실
- AI 근거 검토
- 대중 판단 비율
- 대표 근거

주장 검증형은 출처 또는 참고 자료 입력을 필수로 둔다.

### 3.2 찬반 판단형

어떤 의견, 정책, 행동, 선택에 대해 찬성/반대/중립을 판단하는 유형이다.

예시:

```text
주 4일제 도입에 찬성하는가?
이 서비스 정책은 합리적인가?
```

결과 형태:

- 찬성
- 반대
- 중립
- 각 입장의 대표 근거
- 대중 또는 타깃 집단의 시선 요약

찬반 판단형은 입장과 근거의 논리적 연결성을 AI가 검수한다.

### 3.3 선택 비교형

여러 선택지 중 어떤 것이 더 적절한지 판단하는 유형이다.

예시:

```text
여성용품 A와 B 중 어떤 타입의 사용감이 더 좋은가?
광고 문구 A와 B 중 어느 쪽이 더 설득력 있는가?
```

결과 형태:

- 선택지별 투표 비율
- 선택 이유
- 타깃 사용자 경험 요약
- 대표 의견

선택 비교형은 비교 대상 정보가 필수다.

## 4. 주제 생성 정책

### 4.1 초기 정책

초기에는 운영자 또는 관리자만 주제를 생성한다.

목적:

- 사이트 오염 방지
- 무의미한 주제 확산 방지
- AI 검수 기준 학습
- 결과 품질 관리
- 서비스의 의도된 사용 방식 검증

### 4.2 확장 후 정책

추후에는 사용자가 주제를 제안할 수 있다. 단, 사용자가 올린 주제는 즉시 공개되지 않는다.

사용자 주제 제안 흐름:

```text
사용자 주제 제안
-> 주제 유형 선택
-> 유형별 입력 폼 작성
-> 출처/비교 대상/배경 정보 입력
-> AI가 주제 타당성, 위험도, 중복 여부 검토
-> 필요 시 운영자 최종 승인
-> 승인된 주제만 투표로 전환
```

주제 검수 기준:

- 질문이 명확한가?
- 주장 검증형, 찬반 판단형, 선택 비교형 중 분류 가능한가?
- 특정 개인이나 집단을 공격하지 않는가?
- 명예훼손, 혐오, 선동, 허위정보 확산 위험이 없는가?
- 이미 유사한 주제가 존재하지 않는가?
- 투표자가 판단할 수 있을 만큼 배경 정보가 충분한가?
- 주장 검증형의 경우 출처가 포함되어 있는가?
- 선택 비교형의 경우 비교 대상 정보가 충분한가?

## 5. 타깃 사용자 선별

모든 주제에 모든 사용자를 참여시키지 않는다. 주제 특성에 따라 적합한 사용자를 먼저 선별한다.

기본 방식:

```text
주제별 타깃 조건 적용
-> 조건에 맞는 사용자 풀 생성
-> 무작위 알림 발송
-> 선착순 참여
-> AI 검수 통과 의견만 유효 투표 반영
```

예시:

```text
주제: 여성용품 A/B 사용감 비교
타깃 조건:
- 여성
- 최근 6개월 내 해당 제품군 사용 경험 있음
- 20~40대
- 선택 조건: 민감성 피부 여부
```

사용자 선별 정보는 두 방식으로 수집한다.

1. 회원가입 또는 프로필 작성 시 기본 정보 수집
2. 투표 참여 전 주제별 스크리닝 설문으로 추가 정보 수집

기본 프로필 예시:

- 성별
- 연령대
- 지역
- 관심사
- 주요 소비 카테고리
- 직업군 또는 생활 유형

주제별 스크리닝 예시:

- 최근 6개월 내 해당 제품을 사용한 적이 있는가?
- 해당 주제에 직접 경험이 있는가?
- 특정 서비스나 브랜드를 이용해본 적이 있는가?
- 비교 대상 A/B를 모두 알고 있는가?

## 6. 투표 검수 정책

투표는 제출 즉시 결과에 반영되지 않는다.

사용자는 투표 선택과 근거 의견을 제출하고, 시스템은 이를 AI로 검수한다.

공통 무효 기준:

- 무성의 응답
- 복붙 응답
- 욕설 또는 비방
- 주제 이탈
- 근거 없음
- 선택한 입장과 근거가 연결되지 않음

유형별 추가 기준:

- 주장 검증형: 사실 주장과 출처의 타당성 검토
- 찬반 판단형: 입장과 근거의 논리적 연결성 검토
- 선택 비교형: 선택한 대안과 근거의 관련성 검토

검수 결과 상태:

```text
검수 중
유효 투표 반영 완료
반영 제외
무효 처리
추가 검수 중
```

사용자에게 보여줄 표현:

- 의견 제출 완료
- 검수 중
- 유효 투표 반영 완료
- 투표 반영 제외
- 추가 검수 중

무효 또는 반영 제외 시에는 간단한 사유와 개선 가이드를 제공한다.

예시:

```text
선택한 입장과 근거의 연결이 약해 투표에 반영되지 않았습니다.
다음에는 왜 그렇게 생각하는지 구체적인 경험이나 이유를 적어주세요.
```

## 7. 결과 표현 방식

결과는 AI와 대중 판단을 분리해서 보여준다.

기본 구조:

```text
대중 판단
AI 근거 검토
최종 라벨
대표 근거
무효 처리 통계
참여 조건
```

예시:

```text
주제: 전자레인지에 플라스틱 용기를 돌리면 위험하다

대중 판단:
- 진실에 가깝다: 68%
- 거짓에 가깝다: 12%
- 불확실하다: 20%

AI 근거 검토:
- 다수 의견의 근거는 타당함
- 단, 플라스틱 종류에 따라 위험도가 다름
- 추가 출처 확인 필요

최종 라벨:
- 조건부로 진실에 가까움

무효 처리:
- 17개
- 근거 없음 8개, 주제 이탈 5개, 복붙 4개
```

중요한 원칙:

- 사이트가 절대적 진실을 선언하지 않는다.
- 대중의 판단과 AI 검토를 분리해서 보여준다.
- 결과가 어떤 조건과 표본에서 나왔는지 명확히 표시한다.

## 8. 투표 종료 기준

무제한 누적형 투표는 사용하지 않는다. 리서치 정보의 유효성을 위해 결과가 언제 확정되었는지 명확해야 한다.

기본 방식은 **인원 + 시간 혼합형**이다.

예시:

```text
목표 유효 투표: 100명
최소 유효 투표: 30명
기간: 7일

100명 달성 시 조기 종료
7일 종료 시 30명 이상이면 결과 확정
30명 미만이면 결과 미확정
```

투표 제한 옵션:

- 목표 유효 투표 수
- 최소 유효 투표 수
- 시작일
- 종료일
- 조기 종료 가능 여부
- 타깃 사용자 조건

## 9. 포인트 보상 정책

보상은 제출 자체가 아니라 유효한 기여에 지급한다.

### 9.1 기본 보상 단계

1. 의견 제출
   - 사용자가 투표 선택과 근거 의견을 제출한다.
   - 상태는 검수 중으로 표시한다.
   - 아직 포인트는 확정 지급하지 않는다.

2. AI 검수 실패
   - 무성의, 복붙, 욕설, 주제 이탈, 근거 부족 등으로 판단된 경우.
   - 투표 결과에 반영되지 않는다.
   - 사유에 따라 0P 또는 아주 소량의 포인트만 지급한다.
   - 사용자에게 실패 사유와 개선 가이드를 보여준다.

3. AI 검수 통과
   - 근거가 타당하고 주제와 연결된 의견으로 판단된 경우.
   - 유효 투표로 결과에 반영된다.
   - 기본 참여 포인트를 지급한다.
   - 상태는 유효 투표 반영 완료로 표시한다.

4. 주제 결과 확정
   - 목표 유효 투표 수와 시간 조건을 충족해 주제가 완료된 경우.
   - 해당 주제에 유효 투표로 반영된 참여자에게 추가 포인트를 지급한다.
   - 완료되지 않은 주제는 추가 포인트를 지급하지 않거나 낮은 보상만 유지한다.

### 9.2 주제 제안자 보상

추후 사용자 주제 제안 기능이 열리면 주제 제안자도 보상을 받을 수 있다.

조건:

- 주제가 AI/운영자 검수를 통과한다.
- 주제가 실제 투표로 전환된다.
- 결과 확정 조건을 충족한다.

결과가 확정되지 않은 주제는 주제 제안자 보상을 지급하지 않는다.

### 9.3 이벤트 보상

이벤트 보상은 MVP 핵심 정책이 아니라 추후 기능으로 둔다.

예시:

- 첫 유효 투표 참여 100P
- 개인 누적 10번째 유효 투표 보너스
- 개인 누적 100번째 유효 투표 1000P
- 특정 기간 내 유효 투표 5회 참여 보너스
- 기업 리서치 캠페인 참여 보너스

이벤트 기준은 주제의 100번째 투표자가 아니라, 사용자 개인의 누적 유효 참여 이정표를 기준으로 한다.

## 10. 수익 모델

포인트 재원은 아래에서 나온다.

- 기업 리서치 요청 수익
- 사이트 광고 수익
- 특정 캠페인성 리서치 예산

기업 리서치 요청의 경우, 리서치 요청자가 지불한 비용의 일부를 유효 참여자에게 포인트로 배분할 수 있다.

사이트 광고 수익은 사용자 참여 보상 또는 이벤트 포인트 재원으로 활용할 수 있다.

## 11. MVP 범위

초기 MVP에 포함할 것:

- 운영자/관리자 주제 생성
- 혼합형 주제 유형: 주장 검증형, 찬반 판단형, 선택 비교형
- 타깃 조건 기반 사용자 선별
- 회원가입 시 기본 프로필 수집
- 투표 전 주제별 스크리닝 설문
- 투표 선택 + 근거 의견 제출
- AI 검수
- 검수 중/반영 완료/반영 제외 상태 표시
- 인원 + 시간 혼합형 종료 기준
- 대중 판단 + AI 근거 검토 결과 화면
- 기본 포인트 정책 1-4단계

초기 MVP에서 제외할 것:

- 사용자 자유 주제 생성
- 무제한 누적형 투표
- 정치/여론조사 수준의 대표 표본 주장
- 복잡한 커뮤니티 토론 기능
- 개인 누적 이벤트 보상
- 고도화된 광고 수익 분배
- 완전 자동 리포트 판매 시스템

## 12. 최종 도메인 문장

Opinion Brief는 다양한 주제에 대해 적합한 사용자를 선별하고, 근거 있는 투표를 AI로 검수해, 유효한 대중 판단과 타깃 사용자 경험을 보여주는 보상형 의견 판별 플랫폼이다.

사용자는 단순히 클릭으로 투표하는 것이 아니라 근거를 제시해야 하며, AI 검수를 통과한 의견만 결과에 반영된다. 주제는 주장 검증형, 찬반 판단형, 선택 비교형으로 나뉘고, 각 유형에 맞는 검수 기준과 결과 표현 방식을 가진다. 투표는 인원과 시간 조건으로 종료되며, 유효한 기여에 대해서만 포인트가 지급된다.
