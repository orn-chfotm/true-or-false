# skill · rule 템플릿

이 문서는 rule·skill Markdown의 역할 서술, 연관 관계, 금지사항과 표준 작성 구조를 정의한다.

# 적용 기준

이 문서는 tool adapter(`.claude/rules`, `.claude/skills`, `.agents/skills` 등)의 rule md와 skill md 작성 구조를 정의한다. 각 파일의 담당 범위를 유지하면서 AI가 적용 조건·금지사항·작업 절차·검증 기준을 구분할 수 있도록 작성한다.

# [금지사항]

- 다른 문서의 역할이나 정책을 이 문서의 역할로 재정의하지 않는다. 필요한 규칙은 `연관 관계`에서 `@경로`로 참조한다.
- 한 문서를 수정하면서 다른 문서의 정책·책임 범위를 침범하거나 덮어쓰지 않는다. 문장과 구조를 정리할 때도 기존 파일별 경계를 유지한다.
- 금지사항 없이 skill을 만들지 않는다. 기존 금지사항을 일반 권고로 완화하거나 누락하지 않는다.
- skill description에 트리거 조건 없이 기능 설명만 적지 않는다.
- 다른 문서와의 관계를 경로만 나열하거나 본문에 섞어 모호하게 두지 않는다. `연관 관계`에 참조 목적과 `@경로`를 함께 적는다.

# 작성 원칙

1. **서론에는 해당 문서의 역할만 명시한다.** 다른 문서의 역할을 현재 문서의 책임으로 서술하지 않는다. 필요한 규칙의 참조와 가져오기는 허용한다.
2. **다른 문서와의 연결은 `# 연관 관계`로 분리한다.** `- 참조 목적: @파일경로` 형식으로 작성하며, 경로는 프로젝트 루트 기준으로 지정한다.
3. **금지사항은 문서 상단의 `# [금지사항]`에 모은다.** 각 항목은 금지하는 행동을 먼저 적고, 대체 행동과 이유를 필요한 만큼 덧붙인다.
4. **규칙을 지킨 코드 예시를 제공한다.** 예시만으로 적용 패턴을 이해할 수 있게 작성한다.
5. **skill description에는 기능과 사용 조건을 함께 적는다.** AI가 description만 읽고도 사용 여부를 판단할 수 있어야 한다.
6. **체크리스트와 산출물로 완료 기준을 정한다.** 체크리스트는 검증 가능한 문장으로, 산출물은 보고용 md 템플릿으로 작성한다.

# rule md 표준 구조

rule은 지켜야 할 정책과 판단 기준을 정의한다. 금지사항·설계 기준·예시·구현 가드레일·검증 기준을 구분한다.

````md
# NN. <규칙 이름>

<이 문서가 담당하는 역할만 한 줄로 서술>

# 연관 관계

- <참조 목적>: @<프로젝트 루트 기준 담당 문서 경로>

# [금지사항]

- <금지하는 행동>. <대체 행동과 필요한 이유>.

# 설계 기준

<판단 기준과 이유>

# 예시

<규칙을 지킨 코드/구조 예시>

# 구현 가드레일

- <구현 시 지킬 사항>

# 검증 기준

- <테스트/리뷰로 확인할 항목>
````

# skill md 표준 구조

skill은 작업 절차를 정의한다. 아래 섹션 순서를 유지한다.

````md
---
name: <skill-name>
description: "<무엇을 하는 절차>. <어떤 상황일 때> 사용한다."
---

# <skill-name>

<이 문서가 담당하는 역할만 한 줄로 서술>

# 연관 관계

- <참조 목적>: @<프로젝트 루트 기준 담당 문서 경로>

# 언제 사용하나

- <트리거 상황 2~4개>

# [금지사항]

- <금지하는 행동>. <대체 행동과 필요한 이유>.

# <도메인 기준 섹션>

<선택: FSD 배치, 설계 원칙, 사용자군 경계 등>

# 절차

1. <작업 단계와 해당 단계에서 참조할 rule 경로>

# 예시

<필요한 경우 코드/구조 예시>

# 체크리스트

- [ ] <검증 가능한 문장>

# 산출물

```md
## <보고 제목>

- <항목>:
```
````

# 섹션 규칙

- 다른 문서의 규칙을 참조하면 `연관 관계`에 참조 목적과 `@경로`를 명시한다. 각 규칙의 정의와 변경 책임은 해당 문서에 유지한다.
- skill에는 `언제 사용하나`와 `[금지사항]`을 반드시 둔다.
- 문서 본문의 주요 섹션은 `#`, 하위 섹션은 `##`로 구분한다. 일반 지침을 `[금지사항]`의 하위 섹션으로 배치하지 않는다.
- 도메인 기준 섹션(FSD 배치, 설계 원칙 등)은 금지사항과 절차 사이에 둔다.
- `예시`는 선택이지만 절차만으로 구조가 모호하면 추가한다.
- `체크리스트`는 절차의 반복이 아니라 결과를 검증하는 확인 지점으로 작성한다.
- `산출물`은 사용자 또는 다음 역할에게 보고할 md 템플릿으로 제공한다.
