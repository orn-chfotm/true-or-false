# 오류 처리

이 문서는 오류 분류, 에스컬레이션, 재작업과 절차 재진행 기준을 정의한다.

# 연관 관계

- 리뷰 로깅 참조: @.claude/rules/harness/10-review-logging.md

# [금지사항]

- 발견한 오류를 숨기지 않는다.
- PA는 새 지시 없이 실패 항목을 임의로 우회하거나 범위를 확장해 재진행하지 않는다.

# 오류 분류

- 실행 오류: 명령, 빌드, 테스트 실행 중 발생
- 구현 오류: 요구사항과 다른 동작
- 통합 오류: PA 작업 간 충돌
- 설계 오류: CTO 방향 또는 PL 계획과 충돌
- 승인 오류: 사용자 승인 범위를 벗어난 작업

# 처리 기준

- 실행 오류는 PA가 원인을 정리해 PL에게 보고한다.
- 통합 오류는 PL이 작업 경계를 재조정한다.
- 설계 오류는 CTO 검토로 되돌린다.
- 승인 오류는 사용자 승인 요청으로 되돌린다.
- PA가 에러 또는 불가 처리를 보고하면 PL은 상위 처리 단계가 필요한지 판단한다.
- 상위 처리 단계가 필요하면 PL은 PM, CTO, PL 중 해당 단계에 보고하고 새 판단을 받은 뒤 절차를 재진행한다.
- 재현 가능한 오류와 크리티컬 문제는 `10-review-logging.md` 기준에 따라 실제 프로젝트에 기록한다.

# 재작업 기준

- 범위 오류: PM 단계
- 기술 방향 오류: CTO 단계
- 작업 분리 오류: PL 단계
- 구현 오류: PA 단계
- 검증 오류: review 단계

# PA 에러/불가 보고 형식

```md
## PA 에러/불가 보고

- 작업 ID:
- 작업 실행 주제:
- 수정 파일:
- 현재 결과:
- 에러/불가 사유:
- 영향 범위:
- 재현 또는 확인 방법:
- 필요한 상위 처리 단계:
- 절차 재진행 제안:
```

# 절차 재진행 기준

PA 에러/불가 보고 후에는 다음 순서로 처리한다.

1. PA가 작업을 멈추고 PL에게 보고한다.
2. PL이 원인을 분류하고 필요한 상위 처리 단계를 정한다.
3. 상위 단계가 PM 또는 CTO이면 PL이 해당 단계에 보고한다.
4. 상위 단계 판단으로 작업 범위, 기술 방향, 작업 분리가 갱신되면 해당 단계부터 다시 진행한다.
5. PL이 새 PA 작업 지시를 만든 뒤 PA가 재진행한다.

# 기록 기준

다음 오류는 반드시 로그로 남긴다.

- 같은 원인으로 반복될 수 있는 오류
- 테스트 실패
- 빌드 실패
- 보안 또는 권한 관련 오류
- 데이터 손상 가능성이 있는 오류
- 사용자 승인 범위를 벗어난 변경
