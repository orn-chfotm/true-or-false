# frontend-component-review

프론트 컴포넌트/화면이 `.claude/rules/frontend/01~05`를 지키는지 점검하는 절차다.

## 언제 사용하나

- 새 화면/컴포넌트를 추가할 때
- 상태 관리·데이터 흐름을 바꿀 때
- 프론트 PR을 리뷰할 때

## 절차

1. 대상 컴포넌트가 어느 표면(requester/participant/admin)에 속하는지 확인한다. (`01-app-surfaces.md`)
2. 관련 룰을 매핑한다. (상태 → 02, 폼 → 03, 검수 상태 → 04, 리포트 → 05)
3. 아래 체크리스트로 위반을 찾는다.
4. 룰에 없는 새 패턴이 필요하면 임의 도입하지 말고 룰 문서 갱신을 제안한다.

## 체크리스트

- [ ] 컴포넌트가 하나의 사용자군 표면에만 속하는가?
- [ ] 서버 데이터를 TanStack Query로 관리하는가? 전역 스토어에 복제하지 않았는가?
- [ ] API 호출이 query/mutation 훅으로 분리됐는가? 컴포넌트 본문에서 직접 fetch하지 않는가?
- [ ] 폼이 RHF + Zod를 쓰는가? 검증이 스키마 한 곳에 모였는가?
- [ ] 검수 상태를 "검수 중"부터 표시하고, 도메인 문구만 노출하는가?
- [ ] 리포트가 신뢰 라벨·방법론 주석을 항상 표시하는가?
- [ ] 원문/개인정보를 프론트에서 조합·노출하지 않는가?
- [ ] 타입에 `any`를 남발하지 않는가?

- 수정 방향:
- 룰 문서 갱신 필요 여부:
