# opinion-review-evaluation

이 스킬은 사용자 의견 검수의 판정 품질, 사용자 피드백과 장애 경로를 평가하는 절차다.

# 언제 사용하나

- 검수 모델·프롬프트·점수 기준을 선택하거나 변경할 때
- 정상 의견 오거절, 부실 의견 통과, 부적절한 피드백을 재현할 때
- 검수 구현의 출시 전 평가나 회귀 검증을 수행할 때

# [금지사항]

- Codex 또는 특정 모델의 검수 우위를 전제하지 않는다. 같은 사례·평가 기준으로 비교한다.
- mock 테스트 통과를 실제 모델의 판정 품질로 보고하지 않는다. 계약 테스트와 모델 평가를 구분한다.
- 정답을 모델에게 알려주거나, 프롬프트 조정용 사례만으로 최종 성능을 보고하지 않는다.
- 애매한 의견을 억지로 정답·오답으로 분류하지 않는다. 사람 판정에도 수동 검토와 그 근거를 허용한다.
- 다른 입장·짧은 문장·서툰 문체 자체를 저품질 정답으로 라벨링하지 않는다. 주제 관련성과 근거를 평가한다.
- 수동 전환으로 오류율을 숨기지 않는다.
- 평균 점수만으로 모델의 우위를 결론내리지 않는다.

# 평가 사례

| 범주 | 확인할 행동 |
|---|---|
| 공통 | 무성의·주제 이탈·욕설·근거 없음·선택과 이유 불일치, 짧지만 타당한 의견 |
| 주장 검증형 | 출처와 주장 일치·모순·자료 부족. URL만 있는 경우 읽지 않은 내용을 검증했다고 하지 않음 |
| 찬반 판단형 | 찬성·반대·중립 모두 같은 논리 기준 적용, 모델의 선호와 다른 타당한 의견 승인 |
| 선택 비교형 | 선택한 대안의 속성·제공 정보·사용 경험과 이유의 연결 |
| 복붙·중복 | 비교 대상이 있는 중복과 단지 표현이 비슷한 독립 의견 구분 |
| 프롬프트 인젝션 | 의견·출처 안의 판정 조작 지시를 따르지 않음. 정상 인용문과 공격도 구분 |
| 사용자 피드백 | 실제 입력에 근거한 한국어 사유와 실행 가능한 개선 가이드, 사실·출처를 지어내지 않음 |

# 절차

1. [연동 스킬](../spring-ai-opinion-review/SKILL.md)의 계약과 현재 모델·프롬프트 버전을 확인한다. 판정 기준과 점수 범위가 미확정이면 평가 전에 확인한다.
2. 개인정보를 제거한 사례에 `case_id`, 주제 유형, 전체 검수 입력, 사람의 기대 판정·사유를 기록한다. 정상·거절·수동 검토 사례를 포함하고 프롬프트 조정 세트와 최종 평가 세트를 분리한다. 초기 50~100건은 제안 규모이며 제품 요구사항이 아니다.
3. 실제 모델을 호출하지 않는 계약 테스트를 작성한다. 세 판정, 필수 필드 누락, 미등록 enum, 범위 밖 점수, 비정상 JSON, 타임아웃·호출 오류, 재시도 소진을 확인한다. 모두 실제 상태 저장·수동 전환 결과까지 검증한다.
4. 작업 테스트로 재시작 복구, 같은 job 중복 실행, 검수 결과 저장 실패, 수동 판정 후 지연된 AI 완료를 확인한다. 최종 상태·집계·보상이 합의한 정책을 지키는지 검증한다.
5. 실제 모델 평가는 별도로 실행한다. 같은 사례·자료·평가 기준과 비교 가능한 실행 설정을 사용하고, 모델·프롬프트·설정·데이터 버전을 기록한다. 실제 API 호출은 사용자에게 허용된 비용·데이터 범위에서 수행한다.
6. 아래 지표를 전체와 유형별로 계산한다. 작은 표본의 비율만 내지 말고 분자·분모와 오판 사례도 남긴다. 문구 완전 일치 대신 판정·사유 타당성과 피드백의 사실성을 평가한다.
7. 통과 기준은 측정 전에 합의한다. 프롬프트 변경 후 동일 평가 세트로 회귀를 확인하고 변경 전후 결과를 보관한다. 반복 시 판정이 흔들린 사례는 별도로 기록한다.

# 지표

- 오거절률: 사람이 승인한 사례 중 모델이 거절한 수 / 사람이 승인한 수.
- 부실 의견 승인율: 사람이 거절한 사례 중 모델이 승인한 수 / 사람이 거절한 수.
- 수동 검토 비율 및 3종 판정 혼동표.
- 형식·호출 실패율, 피드백 타당성, 처리 시간과 제공되는 토큰·비용 정보.
- 분모가 0이면 비율은 해당 없음으로 표시한다.

# 체크리스트

- [ ] 정답 누출 없이 고정된 평가 세트로 비교했는가?
- [ ] 장애를 의견 거절과 구분하고, 중복 완료·수동 판정 충돌을 검증했는가?
- [ ] 전체·유형별 오판과 수동 검토 비율, 피드백 품질을 보고했는가?
- [ ] 모델 평가를 실행하지 못한 경우 이유를 명시했는가?
